# Remote FPGA testbed

Django-сервер с React-интерфейсом и агент для Raspberry Pi. Агент умеет работать
с DE10-Lite, GPIO и камерой либо полностью симулировать железо.

## Установка

На одной Raspberry Pi:

```bash
./server/install.sh
./agent/install.sh --mode hardware
```

Оба сервиса запускаются сразу и добавляются в автозапуск. Сервер сам создаёт
секреты и токен, а соседний агент сам их подхватывает. Интерфейс доступен на
`http://<ip-адрес>:8000`.

Для проверки без платы:

```bash
./server/install.sh --no-service
./agent/install.sh --mode simulation --no-service
./server/run.sh
# во втором терминале:
./agent/run.sh
```

Если сервер и агент находятся на разных машинах, сервер напечатает токен. На
Raspberry Pi укажите адрес сервера и этот токен:

```bash
./agent/install.sh --mode hardware --server http://192.168.1.10:8000 --token <токен>
```

Настройки конкретной машины лежат в `server/.env` и `agent/.env`. Шаблоны со
всеми доступными параметрами — `.env.example` рядом с ними. Режим агента
переключается одной строкой: `MODE=hardware` или `MODE=simulation`.

Отключить автозапуск:

```bash
sudo systemctl disable --now fpga-server fpga-agent
```

Логи:

```bash
journalctl -u fpga-server -u fpga-agent -f
```

Агент также пишет в `agent/logs/agent.log`: до 5 МиБ на файл и три архивных
файла. Путь можно изменить через `LOG_FILE` в `agent/.env`. Файл остаётся после
закрытия терминала; сам процесс без systemd после закрытия терминала может
завершиться.

При каждом запуске `server/run.sh` применяются миграции и обновляется токен
агента с именем `AGENT_NAME` из `server/.env`. Для смены токена задайте одинаковый
`AGENT_TOKEN` на сервере и соответствующем агенте и перезапустите оба сервиса.
Другие агенты в базе не меняются.

## Второй testbed и распиновка

На сервере создайте второго агента:

```bash
cd server
.venv/bin/python manage.py create_agent testbed-2
```

Команда напечатает его токен. На второй Raspberry установите агент с адресом
того же сервера и этим токеном. У каждого агента свой токен и своя плата.
Для смены токена второго агента используйте ту же команду с `--token` и
обновите его `agent/.env`.

BCM-пины задаются только в `GPIO_PINS` соответствующего `agent/.env`, в порядке
логических GPIO 1–8. Агент сообщает их серверу при heartbeat; UI сессии и
документация показывают распиновку выбранного testbed. До первого сообщения
BCM помечены как неизвестные, а не подменяются дефолтом. После изменения
`GPIO_PINS` перезапустите агент. DE10/FPGA-пины примера остаются фиксированными:
проводку и проект FPGA всё равно необходимо согласовать физически.

Актуальные названия — `testbed`, `/api/testbeds/` и Python-пакет
`remote_testbed`.

## Возможности

- асинхронная задача: `.svf` и необязательный сценарий `.txt` → видео результата;
- синхронная сессия: живое видео, GPIO 1–8 и загрузка SVF;
- реальное железо через OpenOCD, lgpio и V4L2/ffmpeg;
- режим симуляции без Raspberry Pi, FPGA и камеры;
- гостевые задачи и панель персонала `/monitor`.

Примеры для DE10-Lite находятся в `server/examples/de10_lite/`: настоящая
прошивка Blink и GPIO-тест с полным Quartus-проектом. Распиновка показана на
странице `/docs/fpga`.

## Разработка и тесты

```bash
cd server && .venv/bin/python manage.py test jobs
cd agent && .venv/bin/python -m unittest discover -s tests -t .
```

После установки обеих частей: `server/.venv/bin/python server/scripts/check_startup.py`
из корня проекта проверяет настоящий запуск сервера и simulation-агента в
временной копии: создание чистой базы, смену токена и передачу нестандартных BCM.
Рабочие конфиги и база не затрагиваются.

Vite нужен только при изменении фронтенда: `cd server/frontend && npm run dev`.
